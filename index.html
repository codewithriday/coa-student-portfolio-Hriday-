Why is GPU Faster than CPU?

A Graphics Processing Unit (GPU) handles tasks involving lots of repetitive calculations much faster than a Central Processing Unit (CPU). That's because a GPU contains hundreds or thousands of smaller cores working together at the same time—a process known as parallel processing.

This makes it super efficient for graphics rendering, gaming, video editing, and AI tasks. On the other hand, a CPU has fewer but more powerful cores built to execute sequential tasks one by one. So while a CPU handles everyday general computing better, a GPU excels at heavy, parallel workloads.

What is the Stampeding Herd Problem?

The Stampeding Herd Problem happens when multiple threads or processes are waiting for a single shared resource. The moment that resource opens up, all of them try to access it at the exact same time. This sudden surge overloads the CPU, causing heavy processing overhead and slowing down the system's performance.

💡 Classroom Analogy: You can imagine it like students standing outside a classroom before a lecture. As soon as the teacher opens the door, everyone tries to rush in together. Instead of getting in smoothly, people get stuck in the doorway and everything becomes crowded and slow. The same thing happens in computers when many processes compete for one resource simultaneously.

Introduction

Memory is the part of a computer that stores programs and data. The CPU keeps asking memory for instructions and operands, so the speed of memory directly affects the speed of the whole system. A modern CPU can work in a fraction of a nanosecond, but main memory (RAM) is much slower. If the CPU had to wait for RAM on every access, it would spend most of its time idle.

Cache memory solves this problem. It is a small and very fast memory that keeps copies of the data and instructions the CPU is likely to need soon. It is placed between the CPU and RAM so that most requests can be answered quickly from the cache, and only a few have to go to the slower RAM. Because of this, the average time taken to read data falls sharply and the processor performs better.

2

A processor makes 1,000 memory accesses. Of these, 850 are found in the cache (hits) and 150 are not (misses). The values given in the assignment are shown below:

Problem statement in my own words: We have to find out how well the cache is working by calculating its hit ratio and miss ratio. Then we have to find the average time needed for one memory access (AMAT) and show how this time depends on the hit ratio.

Definition & Characteristics of Cache Memory

Definition

Cache memory is a small, high-speed memory that stores copies of frequently used data and instructions from main memory so that the CPU can get them quickly.

Purpose

Its job is to reduce the speed gap between the fast CPU and the slow RAM, so the CPU waits less for data.

Location in Memory Hierarchy

In the memory hierarchy, the order from fastest to slowest is registers, cache, main memory, and secondary storage. Cache sits just below the registers, between the CPU and RAM. Many processors have more than one level (L1, L2, L3), with L1 being the smallest and fastest.

Architectural Importance

Cache is costly and small, but because programs reuse data, even a small cache answers most requests. This gives performance close to a fast memory at the cost of a much cheaper one.

5

Distinguishing Cache Hits vs Cache Misses

A cache hit happens when the data the CPU asks for is already present in the cache. A cache miss happens when it is not present, so the data must be brought from RAM.

Point Cache Hit Cache Miss
MeaningRequested data is found in the cache.Requested data is not in the cache.
What happensData goes to the CPU straight from the cache.The block is fetched from RAM, copied into the cache, and then given to the CPU.
Performance impactFast. Takes only the hit time (2 ns here).Slow. Takes the hit time plus the miss penalty (2 + 50 = 52 ns here).
Simple exampleReading the same array element again inside a loop.Reading a variable for the very first time.
6

Cache Hit Ratio Calculation

The hit ratio is the fraction of memory accesses that are found in the cache.

Hit Ratio = Number of Cache Hits ÷ Total Memory Accesses
Given: Cache hits = 850, Total accesses = 1,000
Hit Ratio = 850 ÷ 1,000
Hit Ratio = 0.85
Result: Hit ratio = 0.85, or 85%
7

Cache Miss Ratio Calculation

The miss ratio is the fraction of accesses that are not found in the cache.

Miss Ratio = Number of Cache Misses ÷ Total Memory Accesses
Given: Cache misses = 150, Total accesses = 1,000
Miss Ratio = 150 ÷ 1,000
Miss Ratio = 0.15
Result: Miss ratio = 0.15, or 15%
Mathematical Relationship: Every access is either a hit or a miss, so the two ratios always add up to 1. Here, 0.85 + 0.15 = 1. Therefore, Miss Ratio = 1 − Hit Ratio, and Hit Ratio = 1 − Miss Ratio.
8

Why Is Locality of Reference Important?

Locality of reference means that programs tend to access the same data, or data close to it, again and again over a short time. A cache works well only because of this behaviour. There are two types:

Temporal Locality

Data used recently is likely to be used again soon.

Example: A loop counter, or a variable inside a loop, is read in every iteration.
Spatial Locality

Data near a recently used address is likely to be used soon.

Example: When a program reads an array one element after another, the next elements are stored next to the current one.

Because of temporal locality, the cache keeps recently used data. Because of spatial locality, a cache copies a whole block of nearby data on one miss, so the next accesses become hits. Good locality therefore gives a high hit ratio and a lower AMAT. Without locality, the cache would miss often and would help very little.

9

Average Memory Access Time (AMAT) Calculation

AMAT is the average time the CPU needs for one memory access, counting both hits and misses. The formula given in the assignment is:

AMAT = Hit Time + (Miss Rate × Miss Penalty)
Given: Hit time = 2 ns, Miss rate = 0.15 (from Q14), Miss penalty = 50 ns
Step 1: Write formulaAMAT = Hit Time + (Miss Rate × Miss Penalty)
Step 2: Substitute valuesAMAT = 2 ns + (0.15 × 50 ns)
Step 3: Multiply first (15% of 50 ns)0.15 × 50 ns = 7.5 ns
Step 4: Add hit timeAMAT = 2 ns + 7.5 ns = 9.5 ns
Final ResultAMAT = 9.5 ns
Difference Between The Three Terms:
  • Hit time (2 ns): The time to access the cache. It is spent on every access, whether hit or miss.
  • Additional miss penalty (50 ns): The extra time spent only on a miss to fetch data from RAM. It is added on top of the hit time.
  • AMAT (9.5 ns): The overall average per access. It is the hit time plus the penalty spread over all accesses (7.5 ns on average).

Three Important Observations

1Effective Cache

A hit ratio of 0.85 means 85 out of every 100 accesses are served by the cache in only 2 ns. Only a small share of requests have to go to the slow RAM.

2Misses Raise AMAT

A hit costs 2 ns, but a miss costs 52 ns. The 15% misses add 7.5 ns to the average, so AMAT becomes 9.5 ns instead of 2 ns. Although misses are fewer in number, each one is very costly.

3Locality Exploitation

Programs with good temporal and spatial locality get more hits, which reduces the miss rate and lowers AMAT. So writing programs that reuse data, and designing caches that exploit this, helps the CPU run faster.

12

Relationship Between Hit Ratio and Average Access Time

Hit ratio and AMAT move in opposite directions. Since Miss Rate = 1 − Hit Ratio, the AMAT formula can be written as AMAT = Hit Time + (1 − Hit Ratio) × Miss Penalty.

Hit RatioMiss RatioPenalty added (ns)AMAT (ns)
70% (0.70)0.300.30 × 50 = 15.02 + 15.0 = 17.0 ns
85% (0.85) – Given Case Study0.150.15 × 50 = 7.52 + 7.5 = 9.5 ns
95% (0.95)0.050.05 × 50 = 2.52 + 2.5 = 4.5 ns

The table shows that when the hit ratio rises from 70% to 95%, AMAT falls from 17.0 ns to 4.5 ns. This is why designers try to raise the hit ratio. In the given scenario, the 85% hit ratio gives an AMAT of 9.5 ns, which is much closer to the cache speed (2 ns) than to the RAM-miss cost (52 ns).

13

Conclusion

This case study showed how to judge the performance of a cache using simple calculations. From 850 hits out of 1,000 accesses, the hit ratio is 0.85 (85%) and the miss ratio is 0.15 (15%). Using the formula AMAT = Hit Time + (Miss Rate × Miss Penalty), the average memory access time comes to 2 + (0.15 × 50) = 9.5 ns.

The result shows why cache memory is so important. It is small, yet it lets the CPU avoid the slow RAM in most accesses, because programs follow temporal and spatial locality. Even a small number of misses affects the average time, since each miss is expensive. Therefore, the hit and miss ratios are the key measures of cache quality. A higher hit ratio means a lower AMAT, less waiting for the CPU, and better overall processor performance.
